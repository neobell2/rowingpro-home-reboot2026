## 이슈 개요

### 현황
- 현재 17개 페이지의 `.astro` 파일이 **스켈레톤 레이아웃** 상태 (SESSION_36 Builder 작업)
- 콘텐츠는 `.md` frontmatter에서 정상 로드되나, **시각적 디자인 요소 부족**

### 구체적 문제 (about.astro 예시)

**있는 것:**
- 텍스트 콘텐츠 (frontmatter 로드)
- glass-panel 기본 레이아웃
- 그리드 카드 구조

**없는 것:**
- 사진/이미지 (창업주 사진, 활동 사진 등)
- 시각적 위계 구조
- 인포그래픽/아이콘
- 섹션 간 시각적 구분
- 브랜드 비주얼 요소

**영향 범위:** 17개 페이지 전부 유사한 상태로 예상

## 문제 인식 근거

### 1. about.astro 분석 (lines 54-68)

```astro
<section class="py-24 bg-deep/50">
  <div class="max-w-7xl mx-auto px-6 lg:px-8">
    <h2 class="text-4xl font-display font-bold text-white mb-12 text-center">{founders.heading}</h2>
    <div class="grid grid-cols-1 md:grid-cols-2 gap-12">
      {founders.items.map((founder: { name: string; bio: string; period: string }) => (
        <div class="glass-panel p-10">
          <h3 class="text-2xl font-bold text-white mb-4">{founder.name}</h3>
          <p class="text-white/80 mb-6">
            {founder.bio}
          </p>
          <div class="text-sm text-white/60">{founder.period}</div>
        </div>
      ))}
    </div>
  </div>
</section>
```

**문제점:**
- 창업주/CEO 섹션에 **사진 없음**
- 단순 텍스트 카드 2개만
- 위계 구조 약함 (Founder vs CEO 구분 불명확)
- 장문 bio가 시각적 피로 유발

### 2. 디렉터 피드백 (원문)

## 해결 방안 (2가지)

### 방안 A: 점진적 폴리싱 (Incremental Polishing)

**접근:**
- 페이지별로 Designer + Builder 협업
- 17개 페이지를 순차적으로 레이아웃 재설계
- 각 페이지마다 시안 → 검토 → 구현 반복

**장점:**
- 페이지별 맞춤 디자인 가능
- 단계적 피드백으로 품질 관리 용이
- 중간 점검 및 방향 수정 가능

**단점:**
- 17번 반복 작업 필요
- 일관성 유지 어려움 (페이지별 디자인 차이 발생 가능)
- 예상 세션: **8~10 세션**

**프로세스:**
```
각 페이지당:
1. Designer: 레이아웃 시안 제작 (사진/비주얼 위치 포함)
2. 디렉터: 시안 검토 및 피드백
3. Builder: 구현
4. 디렉터: 최종 확인
→ 다음 페이지 진행
```

---

### 방안 B: 시안 재생산 (Full Redesign)

**접근:**
- 콘텐츠 17개 확정 후 Designer AI 전체 위임
- 17개 페이지 레이아웃 시안 일괄 제작
- 시안 확정 후 Builder 일괄 구현

**장점:**
- 전체 일관성 확보 (디자인 시스템 적용)
- 병렬 작업 가능 (시안 일괄 제작)
- 예상 세션: **5~8 세션**

**단점:**
- 초기 시안 제작 시간 소요
- 시안 재작업 시 전체 영향
- Designer AI 역량 의존도 높음

**프로세스:**
```
1. 콘텐츠 17개 확정
2. Designer AI: 17개 페이지 레이아웃 시안 일괄 제작
3. 디렉터: 전체 시안 검토 및 피드백
4. Designer AI: 시안 수정 (필요시)
5. Builder: 17개 페이지 일괄 구현
6. 디렉터: 최종 QA
```

---

### 방안 C: 하이브리드 (선택적 조합)

**접근:**
- 주요 페이지 (Index, About, 비즈니스/라이프 허브): 방안 A (점진적 폴리싱)
- 하위 페이지 (서비스 7개, History, Contact): 방안 B (일괄 시안)

**장점:**
- 주요 페이지 품질 확보
- 하위 페이지 효율성 확보
- 예상 세션: **6~9 세션**

**단점:**
- 작업 방식 혼재로 관리 복잡도 증가
- 일관성 유지 위한 추가 조율 필요
