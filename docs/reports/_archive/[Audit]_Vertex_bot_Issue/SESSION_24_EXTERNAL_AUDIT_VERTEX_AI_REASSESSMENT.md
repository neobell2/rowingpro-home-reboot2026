## 2. 제3자 관점의 핵심 쟁점 정리

### 쟁점 A — “지금” 도입해야 하는가? (Need/Timing)
**결론:** “지금”은 **증거 부족**입니다. (도입 자체가 아니라, *도입 시점*이 문제)
- 현재 프로젝트 정의(`01_PROJECT_CONTEXT.md`)는 **“기업소개 + 서비스 안내”**가 1차 목적이며,
- Phase 3/4는 사이트 완성과 Contact 실연동(운영 데이터 생성)을 목표로 합니다.
- AI 자동화는 효과가 있을 수 있으나, **실제 문의량/유형/응답 실패율 데이터 없이** ROI/필요성을 확정하기 어렵습니다.

### 쟁점 B — 기술적으로 가능하더라도 “브랜드/운영/법무”가 가능한가? (Non-Functional)
**결론:** 기술 구현 가능성(가능)과 운영 가능성(불확실)을 분리해야 합니다.
- **브랜드/UI:** 메인아키텍트가 지적한 “위젯 스타일링 제약”은 *프리미엄 다크 톤*을 훼손할 수 있는 실질 리스크입니다.
- **운영 지속성:** 모델/데이터/요금/장애/품질 모니터링을 누가, 어떤 주기로 담당하는지 정의가 필요합니다.
- **개인정보/동의:** 과거 데이터(418건/219+)에 담당자 개인식별정보가 섞였을 가능성이 높고, 챗봇이 이메일을 수집하면 **동의 UI/처리방침 보강**이 필요합니다. (`src/pages/privacy.astro`는 현재 포괄형 서술 수준)

### 쟁점 C — 비용/난이도 정보의 신뢰성
**결론:** 메인아키텍트의 “비용 2~3배 과소평가” 판정은 합리적이며, 의사결정 입력값으로는 메인아키텍트 수치를 채택해야 합니다.
- 원본 제안서는 성격상 “기술 분석서”라기보다 “영업 제안서”에 가깝습니다(메인아키텍트 판단과 동일).
- 따라서 “월 3~8만원” “노코드/7일”은 **감사 기준의 신뢰도 입력값으로 부적절**합니다.

## 3. 독립 판정(Third-Party Verdict)

### 3.1 최종 판정: **HOLD(보류) — 단, ‘검토 중단’이 아니라 ‘조건 충족 후 재판단’**
본 제3자 감사는 메인아키텍트의 결론(2026-02-16)과 동일하게,
**현 시점 즉시 도입은 보류**가 타당하다고 판정합니다.

단, “보류”의 의미는 “거부”가 아니라 다음 조건이 충족될 때까지의 **결정 유예(Decision Deferral)** 입니다.

### 3.2 디렉터 입력 기반 재판정(운영 가정 업데이트)
디렉터 제공 운영 가정:
- **평균 문의량:** 주간 최대 5회(≈ 일 1회 미만)
- **문의 목적:** 견적 + 제안서 요청이 한 세트이며, 상담 요구 수준이 유사

이 가정이 유지되는 한, Vertex AI(위젯+자동화)를 “회사에 필요한 필수 기능”으로 보기 어렵습니다.
- 문의량이 낮아 **자동화 ROI가 낮고**, 반대로 **운영/법무/브랜드 리스크의 상대적 비중이 커집니다.**
- 같은 상담이 반복된다면, AI보다 먼저 **표준 견적/제안서 패키지 + 폼 입력 구조화 + 즉시 회신(자동응답)** 으로 대부분 해결 가능합니다.

### 3.3 예산 제약 기반 재판정(Vertex 예산 140만원/년)
디렉터 추가 입력:
- **Vertex 예산:** 140만원(1년 유효)

스크린샷(Cloud Billing > Credits) 기준 확인된 크레딧:
- **Trial for Gen App Builder:** 잔액 **₩1,430,080**, 시작 **2026-02-15**, 종료 **2027-02-16**
- (참고) **Free Trial:** 잔액 **₩392,157.79**, 시작 **2026-02-10**, 종료 **2026-05-06**

이 예산은 기존 검토(메인아키텍트)의 “현실적 연간 비용(약 192만~283만원)” 가정과 비교할 때,
**제안서의 ‘풀스택(대화형+자동화)’을 1년 상시 운영하기엔 부족**할 가능성이 큽니다.

따라서 예산이 존재한다는 사실은 결론을 “Go”로 바꾸기보다, 아래 중 하나로 “스코프를 축소”하거나 “실험으로 제한”하도록 요구합니다.

**권고 옵션(저위험/예산 친화):**
1. **PoC 예산으로 사용(권고):** 런칭 후 4~8주 데이터 수집 → *짧은 기간(예: 4주)*만 Vertex로 실험하고 성과/비용을 측정한 뒤 종료/확대 결정
2. **Search-only(문서 검색)로 한정:** “생성형 답변/대화형 상담”을 최소화하고, **자료/FAQ/프로그램 문서 검색** 중심으로 제한(환각/브랜드 리스크 감소)
3. **자동화(n8n) 제외:** “제안서 자동 발송”은 Vertex가 아니라 Phase 4의 Resend 자동응답/템플릿으로 처리(비용/운영 복잡도 감소)

**필수 가드레일(예산 140만원일 때는 필수):**
- Google Cloud **Budget/Alert**로 월 상한을 강제(초과 시 즉시 중단)
- “가격/안전/법무” 영역은 **AI 응답 금지** 또는 고정 답변/링크로 제한
- 업로드 데이터는 **PII(이름/직급/연락처) 완전 제거** 후 사용

### 3.4 보류 해제(Go) 최소 조건 (Gate)
아래 5가지가 충족되면 Phase 5(또는 별도 트랙)로 도입 결정을 재개할 수 있습니다.

1. **운영 데이터 확보:** 사이트 런칭 후 4~8주간 문의 데이터(건수/유형/미응답률/응답시간) 수집
2. **목표 정의:** “AI가 해결할 Top 3 작업”을 1문장씩 정의 (예: 야간 문의 1차 응답, 자료 링크 제공, 상담 예약 유도)
3. **대안 비교:** 최소 3개 대안(예: 채널톡/Intercom/Tidio/Vertex AI 또는 “AI 없이 FAQ+Contact 강화”)의 총비용/운영부담 비교
4. **개인정보 설계:** 업로드 데이터 정제 기준(PII 제거 규칙) + 챗봇 수집항목/동의 UI/처리방침 보강 범위 확정
5. **롤백 계획:** 위젯 제거/자동화 중단 시 서비스가 정상 유지되는 “Fallback 경로”(Contact/전화/메일) 문서화

> 참고(정량 트리거 예시): 문의량이 **월 40건(주 10건) 이상**으로 상승하거나, “놓치는 문의(지연/미응답)”가 **20% 이상**으로 확인되면 Gate 충족 여부를 우선 재점검합니다.

## 4. 즉시 실행 권고(Phase 3/4를 방해하지 않는 범위)

아래는 “AI 도입 보류”와 무관하게, **지금** 해도 Phase 3/4 목표에 부합하고 리스크를 낮춥니다.

1. **Contact 실연동 우선:** Phase 4에서 Contact 폼을 완성해 “문의 데이터”를 생성 (AI 판단의 근거 확보)
2. **측정 항목 정의:** 문의 폼에 “문의 유형” 최소 분류(견적/일정/일반문의)를 넣어 재판단 데이터 품질을 올림
3. **처리방침 보강 체크:** 향후 챗봇/자동화 도입 가능성을 전제로, 개인정보 처리방침에 “제3자 처리/국외 이전 가능성/수집 항목” 보강 필요 여부를 사전 체크리스트로 준비

### 4.1 현재 문의 패턴(견적+제안서+상담 유사)에 최적화된 “AI 없는 자동화” 권고
Vertex AI 대신 아래 조합을 우선 권고합니다(Phase 4 범위 내):
1. **견적 폼 구조화:** 날짜/인원/장소/목적/예산 범위/연락처/희망 응답 채널
2. **즉시 자동응답(Resend):** 접수 확인 + 표준 제안서(브로셔) 링크 + 상담 예약(캘린더 링크) + 예상 회신 SLA
3. **내부 알림:** 폼 내용을 구조화해 “한 번에 판단 가능한” 형태로 관리자 이메일 발송(누락/재문의 감소)

## 6. 결론

- 기존 검토 결과 중 **기술 구현 자체는 가능**하다는 점에는 동의합니다(현 코드 구조상 외부 위젯 삽입 가능).
- 그러나 “가능”은 “적절”의 충분조건이 아니며, 현 시점은 **필요성/운영/법무/대안비교**가 미완입니다.
- 따라서 제3자 감사 판정은 **HOLD(보류)**이며, 위 Gate 조건을 충족한 뒤 재판단을 권고합니다.
