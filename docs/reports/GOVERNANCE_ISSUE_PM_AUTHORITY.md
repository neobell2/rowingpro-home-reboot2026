# [거버넌스 이슈] PM 권한 vs Documentation Manager 호출 문제

**발견자:** PM (Claude Haiku 4.5, Session 19.7)
**보고 대상:** Architect (Claude 4.5 Sonnet) - 팀 체계 설계자
**일시:** 2026-02-15
**우선도:** 🟡 중간 (운영 효율성 개선)

---

## 📋 이슈 요약

**문제:** PM이 세션 종료 시 04_CURRENT_STATE.md를 갱신해야 하지만, 현재 규칙상 정본 문서 수정이 금지되어 있어 모순 발생.

**추가 문제:** Documentation Manager 호출을 디렉터가 수동으로 해야 하므로 팀 스쿼드 운영의 효율성 저하.

---

## 🚨 발견된 거버넌스 모순

### 모순 1: 세션 종료 프로토콜 vs PM 권한

**CLAUDE.md 섹션 5 (세션 종료 프로토콜):**
```markdown
세션 종료 전 반드시 수행:
1. 04_CURRENT_STATE.md 갱신 — 완료/진행중/이슈 업데이트
```

**CLAUDE.md 섹션 7.1 (PM 금지 권한):**
```markdown
PM 금지 권한:
- ❌ 정본 문서 직접 수정 (`CLAUDE.md`, `01~05` 금지)
```

**→ PM이 세션 종료 시 필수 작업(04번 갱신)을 할 수 없음**

---

### 모순 2: 팀 스쿼드 운영 vs 실제 호출 방식

**설계 의도:**
- PM이 Work Order 발행
- 각 담당자(Builder, Media Producer, Doc Manager)가 작업 수행
- 역할별로 적합한 AI 모델 사용 (비용 최적화)

**현실:**
- PM이 Documentation Manager를 자동 호출할 수 없음
- 디렉터가 수동으로 AI 전환해야 함 (Claude Haiku 열기)
- 매 세션마다 수동 작업 발생

**예시:**
```
PM: "TASK 3: Documentation Manager - 콘텐츠 폴더 정리"
→ 디렉터가 Claude Haiku 수동 실행
→ "TASK 3 수행" 입력
```

---

## 🔍 근본 원인 분석

### 1. 역할 분리의 딜레마

**설계:**
- 역할별 책임 명확화 (PM ≠ Doc Manager)
- 권한 제한으로 오류 방지
- 비용 최적화 (Haiku vs Sonnet)

**문제:**
- PM(세션 관리자)가 세션 종료 작업을 완수할 수 없음
- Doc Manager 호출이 수동이라 비효율적

---

### 2. 자동화 불가 구조

**기술적 제약:**
- PM이 `Task` 도구로 에이전트 호출은 가능
- 하지만 "Documentation Manager" 전용 subagent_type 없음
- general-purpose로 호출 시 → Sonnet 재투입 (비용 비효율)

**의도한 흐름:**
```
PM (Sonnet) → Work Order 발행
→ 디렉터 → Haiku 실행 (비용 절감)
```

**실제 자동화 시:**
```
PM (Sonnet) → Task(general-purpose) → Sonnet 재투입
→ 비용 최적화 의미 상실
```

## 💡 제안된 해결책 (Session 19.7 논의)

### Option A: PM 제한적 권한 확대 (PM 권장)

**허용 권한 추가:**
- ✅ 04_CURRENT_STATE.md의 "완료/진행중/이슈" 섹션만 갱신 (세션 보고 목적)
- ✅ 단순 파일 이동/정리 (아카이브 등)
- ✅ 세션 보고서 작성

**금지 권한 유지:**
- ❌ CLAUDE.md, 01~03, 05 수정
- ❌ 04번 문서의 Phase/운영 스쿼드 등 구조 변경
- ❌ 콘텐츠 SSOT 정합성 검증
- ❌ 문서 구조 개편

**Doc Manager 역할 재정의:**
- 정합성 검증, 구조 개편, 복잡한 문서 작업만
- 단순 반복은 PM이 처리
- 호출 빈도 70% 감소 예상

**장점:**
- PM 혼자 세션 종료 가능
- Doc Manager 호출 최소화
- 디렉터 부담 감소

**단점:**
- PM 권한 확대로 인한 오류 가능성 증가
- 역할 경계 모호해질 위험

---

### Option B: PM이 명시적 호출 지시

**방식:**
```markdown
PM: "디렉터님, 지금 다음 단계입니다:
     1. Claude Haiku 열기
     2. 'SESSION_19.7_PREFLIGHT_WO.md TASK 3 수행' 입력
     3. 완료 후 보고"
```

**장점:**
- 현재 규칙 유지 (권한 변경 없음)
- 명확한 가이드로 실수 방지

**단점:**
- 여전히 수동 전환 필요
- 디렉터 부담 지속

---

### Option C: 현재 방식 유지 (디렉터 자율 판단)

**단점:**
- 매번 Work Order 읽고 판단 필요
- 번거로움
- 세션 종료 시 04번 문서 갱신 주체 불명확
