# 17페이지 콘텐츠 주입 및 창작 협업 작업계획안

## 1. 목적
- 기존 시안(17페이지)의 **원본 소스 변형 없이**
- 샘플 하드코딩 문장을 실제 콘텐츠로 교체
- 인간 주도 창작 + AI 보조 구조로 효율적 진행
- 토큰 사용량 급증 방지

---

## 2. 역할 분리

### 2.1 인간(카피라이터)
- 최종 창작 책임
- 문장 초안 작성
- 방향성 결정 및 확정

### 2.2 메인 창작 보조
- 웹 Claude (Sonnet 권장)
- 역할: 문장 정제 / 톤 유지 / 리듬 개선 / 문법 교정
- 출력: 2~3개 대안 중심, 설명 최소화

### 2.3 서브 창작 보조
- 웹 Gemini (Pro 또는 Flash)
- 역할: 아이디어 확장 / 관점 다양화 / 발상 전환
- 메인 모델 보완용으로 사용

### 2.4 로컬 프로젝트 매니저 (귀하 담당)
- 페이지 실행 및 실시간 미리보기 유지
- 확정 문장 반영
- 세션 단위 관리
- 원본 구조 보호

---

## 3. 작업 원칙

1. HTML 전체를 AI에 전달하지 않는다.
2. 현재 수정 중인 섹션 텍스트만 전달한다.
3. 페이지 단위로 세션을 종료한다.
4. 확정 전까지는 코드 구조를 수정하지 않는다.
5. AI는 “보조”, 인간이 “결정권자”이다.

---

## 4. 페이지 단위 작업 프로세스

### STEP 1. 페이지 실행
- 로컬 서버로 해당 페이지 실행
- 현재 섹션 시각 확인

### STEP 2. 초안 작성
- 인간이 직접 초안 작성

### STEP 3. 메인 보조 요청
- 웹 Claude에 해당 문장만 전달
- 요청 예시:
  - “선언형 유지, 더 압축”
  - “리듬 개선, 과장 제거”
  - “문법 교정만”

### STEP 4. 화면 확인
- 로컬 반영 후 실제 화면 검증
- 시각적 밀도 / 줄바꿈 / 강조 위치 확인

### STEP 5. 필요 시 서브 보조 활용
- 발상이 막힐 경우 Gemini 활용
- 관점 확장 후 다시 메인 모델로 정제

### STEP 6. 확정
- 확정 시 해당 섹션 완료 표시
- 다음 섹션으로 이동

### STEP 7. 페이지 종료
- 해당 페이지 세션 종료
- 다음 페이지는 새 세션으로 시작

---

## 5. 세션 관리 정책

- 1페이지 = 1세션
- 1세션 최대 처리량: 8섹션
- 페이지 완료 즉시 세션 종료
- 이전 대화 맥락 재사용 금지

---

## 6. 기술적 운영 방식

- 시안 소스는 직접 수정하지 않는다.
- 콘텐츠 교체만 수행한다.
- 필요 시 텍스트 분리 구조(JSON 등)는 추후 도입 가능.
- 자동 코드 생성 기능은 사용하지 않는다.

---

## 7. 기대 효과

- 대규모 프로젝트에서도 토큰 폭증 방지
- 모델 과개입 방지
- 브랜드 톤 일관성 유지
- 인간 주도 창작 유지
- 비용 예측 가능 구조 확보

---

## 8. 모델 사용 전략 요약

- Claude: 중심축 (정제·일관성)
- Gemini: 발상 확장
- 로컬: 최종 판단 기준
